# Split-K 128×64 B32 complete-update evidence

This B32-only opt-in publication draft is pending root review. Other seven
policies, library defaults and strongest historical targets remain unchanged.
The independent audit passes; suite parity remains 2/8.

Two reversed complete-update trials report a 51.754815 ms Square64 baseline and
51.26829125 ms rectangle candidate: 0.940055% aggregate reduction, with trial
reductions of 1.23398% and 0.64499%. The fresh 30.190971247 ms compiled control
is slower than the retained strongest historical 29.499400989 ms control.
There is no confidence or causal claim. Six timing workers, 384 updates and
four unchanged runner comparisons are counted once. The screen and manual
resource/math/census/state tests are separate prequalification.

[Independent audit](independent-audit.json) and [controller audit](controller-timing-audit.json)
retain the numerical, source, state, guard and six-stage memory findings.
[Metadata and guards](metadata-and-guards.tar.gz) contains 253 files at original
workspace-relative paths: both reports, raw process/NVML/desktop data,
controllers, build bindings, manual proof outputs and both Rust source archives.
Every archived member was decompressed and SHA256 verified. Executable and
compiler binaries are omitted; their hashes, sizes and source bindings remain.
The sealed 400-file source archive is also under transformer-training-sources.

[Raw aliases](raw-aliases.json) map 20 fresh screen/timing/reference/fixture paths
to verified byte objects. Native gradient c33e1e63, native weight 3b55fb39 and
fixture weight objects reuse the existing packed-profile raw archive. Six
byte-distinct fresh PyTorch objects are stored once in new-raw-objects.tar.gz.
Both referenced archives were reopened and every referenced object hashed.
Fresh PyTorch snapshots remain separate under unchanged numerical gates; exact
byte equality is asserted only for matching hashes. This avoids more than 1 GB
of pathwise snapshot duplication. The alias manifest records archive/member
paths, hashes and sizes for restoration. The existing packed-profile archive
is a required durable dependency and must remain present.

The actual V4096 census installs 17 rectangles and four old fallthroughs.
Forced late rejection retains 17 complete Square64 programs and the same four
fallthroughs. Synthetic V16384 unique-token state selects 16 rectangles and
compares exact loss, gradients, norm, scale, masters, moments and timestep
through [1,2,1,0] accumulation, NaN rollback and finite recovery. This is separate
from measured V4096 fixed PyTorch gates. The tile leaf compares all four F32
partial planes, final left-associated BF16 arrays, guards and read-only inputs;
one captured graph is reused across feeds. It includes 162 array comparisons,
18 read-only checks and 324 independent dyadic F64 samples, with no timing.

Actual rectangle functions use 96/98 registers, 32,768 shared bytes, no local
bytes and API block capacity two; Square64 uses 80 registers, 18,432 shared bytes
and capacity three. Capacity is not achieved occupancy or a causal latency
explanation. Every paired allocator stage and owned payload byte delta is zero.
Sampled process deltas of −64 and +66 MiB are mixed lower bounds and support
no memory-saving or capacity claim.

Raw guard files lack persisted query start/end and generation-check success
receipts. Normalized-reader timestamps and source checks are retained; sampled
closure cannot prove continuous idleness. CUDA function-handle IDs were not
recorded. Fallback proof combines exact labels, grids, pointers and resources
with sealed whole-tuple selection source and canonical PTX equality. The first
independent revalidation attempt used an interpreter without NumPy; that failure
and the corrected passing attempt are retained outside performance counts.

# B32 register-statistics complete-update evidence

This is a B32-only publication draft pending root review. Other seven policies,
library defaults and strongest historical targets remain unchanged; parity is 2/8.

Two reversed complete-update trials report baseline 51.48708325 ms and candidate
50.87348925 ms, reduction 1.19174356%, with paired reductions 1.127936%/1.255343%.
Fresh compiled control 30.11285925095 ms is slower than the retained strongest
historical 29.49940098915 ms control. No confidence or causal claim is made.
Six timing workers, 384 updates and four unchanged runner comparisons count once.
Screens and manual proofs are separate prequalification.

The candidate adds only --online-attention-register-statistics atop accepted
Rectangle128x64/packed arguments. Four Register forwards replace four Global
forwards. Native information retains 17 rectangle programs, four old fallthroughs and four packed backward regions and
6 MiB statistics in every row. Slots 0/1 remain exact forward exports, slot 2 is
unchanged backward delta, and all ownership/accounting is preserved. Failure
triggers a retry of the whole accepted Global pair; a rejected retry retains
the original graph. No allocation-removal claim is made.

[Independent audit](independent-audit.json), [controller audit](controller-timing-audit.json)
and [build qualification](build-qualification.json) bind full numerical, source,
guard, state and memory findings. metadata-and-guards.tar.gz contains 294 files,
including both reports, raw process/NVML/desktop data, helpers, source bindings,
manually qualified leaf/state outputs, live and isolated 402-file source archives.
Every archived member was decompressed and SHA256 verified. Executables and
compiler binaries are excluded; their hashes/sizes/source bindings are retained.

raw-aliases.json maps 20 fresh screen/timing/reference/fixture paths to verified
byte objects. Native gradient c33e1e63, native weight 3b55fb39 and fixture weights
reuse existing packed-profile content. Six byte-distinct fresh PyTorch objects
are stored once in new-raw-objects.tar.gz; equality with older controls is never
assumed. Both reused and new referenced objects were decompressed and hashed.
This avoids more than 1 GB of pathwise snapshot duplication. Member paths/hashes/
sizes permit restoration; the external packed-profile archive must remain.

Paired leaf math compares 408 complete arrays and 96 read-only inputs with original
exports and unchanged backward. Live V16384 unique-token state compares Global,
Register and forced-resource-Global arms through [1,2,1,0], complete state, NaN
rollback and finite recovery. This scope uses 16 rectangles and is separate from measured
V4096 fixed PyTorch gates with 17 rectangles. The forced hook is not an observed actual
driver failure. All six pool stages/both pools and owned payload deltas are zero;
Each sampled NVML process peak is a lower bound on its true high-water mark;
+66/0 MiB differences are observations, not bounds on the true peak difference
or allocator deltas, and imply no memory-saving/capacity claim. No new profile or causal speed attribution follows.

[Corrected default proof](corrected-default-prefix.json) is authoritative: the
original Global Rust prefix and current default/explicit Scalar IR/PTX identity
are checked. External historical PTX goldens were not bound. A legacy test name
and the earlier builder metadata do not prove historical golden comparison;
the overbroad old wording is retained only as historical evidence.

Raw guard files lack query start/end timestamps and per-query generation-success
receipts. Normalized reader times and source checks are retained; sampled
closure cannot prove continuous idleness or exclude sub-sample activity/PID reuse.
The previous Square64 profile remains historical and predates both B32 options.
